# Баг із межею доби

У щоденному звіті частина подій потрапляла в попередній день.

**Причина.** `new Date(e.at).toISOString().slice(0, 10)` бере дату в UTC. Подія о 01:30 за Києвом (`2026-03-10T01:30:00+02:00`) у UTC ще 23:30 попереднього дня, тож усе з 00:00 до 02:00 (влітку до 03:00) за Києвом ішло у вчорашній день.

**Виправлення** (`src/groupByDay.ts`). День рахується в поясі `Europe/Kyiv` через `Intl.DateTimeFormat`: база поясів сама враховує перехід на літній і зимовий час. Подія без зсуву або з некоректною датою дає помилку: без зсуву результат залежав би від поясу сервера.

**Як перевірено, що тест ловить баг.**
- Перший коміт (`e88a0a6`): старий код і тести, 6 із 8 падають, зокрема ночі переходу 29.03 і 25.10.2026.
- Другий коміт (`021bc69`): виправлення, тести зелені. Якщо повернути старий рядок, ті самі тести знову падають.
- `npm test` запускає тести двічі, з поясом машини UTC і New York, тож рішення, що випадково бере час сервера, не пройде.
- Кожна подальша правка: спершу тест, що падає, окремим комітом, потім виправлення.

**Запуск** (Node.js 22.18+):

```bash
npm install
npm test
npm run typecheck
node demo.ts   # який день був і став для кількох подій
```
